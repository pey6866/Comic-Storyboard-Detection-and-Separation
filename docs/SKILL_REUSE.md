## 输入输出与适配

上游是给开发者/开发代理的推理指导，不是检测模型。输入为模型、图片、配置和开发任务，
经开发工具执行后产生预测、坐标、裁剪和检查记录。上游示例主要为Ultralytics API，
本项目适配到ONNX Runtime，没有调用YOLO或Results接口，没有运行时执行Markdown的机制。

| 指导 | 实际适配与核验 |
|---|---|
| imgsz与导出后处理 | 检查输入640，raw [1,5,N]，自编NMS |
| conf/iou | 第9页对照conf .10/.25/.50和NMS .30/.45/.60，保存框与分数 |
| RGB/BGR | 纯红输入检查RGB、NCHW和归一化 |
| 坐标约定 | 中心宽高转左上角xywh，验证letterbox逆变换 |
| 保存绘图与裁剪 | 检查真实裁剪与原图区域像素一致，保留全部候选与复核状态 |
| 性能排错 | 单独记录加载、预热，再重复5次，仅计推理及前后处理 |
| 异常输入 | 空白0框needs_review，损坏failed，批流程留痕 |

历史正常开发第6页6框；低分第9页6框、needs_review。conf从.10/.25/.50得到6/6/4框；
固定conf=.25，NMS=.30/.45/.60得到5/6/7框。数量变化只证明参数生效，不代表准确率提升。
真实图片不随公开版分发，预览和裁剪也省略；证据JSON可供审阅，不能替代原图复核。

## 重跑与权限边界

需自行准备有权使用的原开发页漫画/*_06.jpg、*_09.jpg及models/best.onnx，执行
python scripts/verify_skill_reuse.py。没有两页时脚本给出明确说明，不伪造真实低分场景。
若换用新图片，应调整案例协议并另存新记录，不能预设仍输出6框或必然低分。
下载skill/权重时需要网络；推理只读本地文件并写结果，不上传图片，不需要账号或API key。
运行时网页Agent为规则工作流，开发辅助skill与模型、执行库的贡献分别记录。
